# Q.ANT boundary-platform audit and existing-NPU experiment

Status: **primary external platform candidate; capability confirmation pending**
Date: 2026-07-26
Consensus status: **none**

## Decision

Q.ANT is the primary external candidate for the next PhotonHash boundary
experiment. Its current Native Processing Unit (NPU) is more directly relevant
to the missing R1 boundary than a linear-only photonic matrix engine because
Q.ANT publicly claims native nonlinear optical processing on a thin-film
lithium-niobate platform.

This designation does not reopen R1, qualify a v0.3 construction, or change the
negative boundary-phase decision. Public evidence does not establish that the
NPU implements an exact discrete transition, keeps recurrent state optical, or
avoids a complete conversion and re-encoding loop between operations.

The next physical step is therefore an existing-NPU capability and measurement
program. A custom laboratory boundary must not be proposed until Q.ANT's
available hardware has either been directly evaluated or Q.ANT confirms that
the required experiment cannot be executed on it.

Lightmatter remains the stronger public example of large photonic matrix
compute and advanced packaging. Q.ANT is the higher-priority boundary platform
because its available hardware explicitly includes native nonlinear optical
processing.

## What public evidence establishes

| Property | Public evidence | PhotonHash interpretation |
|---|---|---|
| Commercial platform | Q.ANT offers Gen-2 NPS systems with PCIe NPUs, C/C++ and Python interfaces, a Linux device driver, and a declared 8 GOPS/150 W NPU specification. | There is an existing platform to evaluate before building custom hardware. The figures do not define an R1 operation or joules per valid attempt. |
| Optical arithmetic | Q.PAL exposes matrix multiplication at the matrix-vector level. Q.ANT's Gen-2 materials also describe optical summation, subtraction, multiplication, squaring, root extraction, Fourier transforms, and native nonlinear processing. | A representative R1 matrix pass is plausible, subject to supported dimensions, ranges, weight residency, batching, and raw-output access. |
| Nonlinear primitive | A 2026 Q.ANT use-case paper describes a weighted sinusoidal function of an input vector produced by controlling PIC modulation. Current product material calls the nonlinear units native to optics. | This is relevant physical nonlinearity, but public material does not freeze a cosine API, transfer function, precision, saturation law, or deterministic threshold behavior. It is not the R1 wrap map. |
| Recurrent workload | Q.ANT reports running the TiRex xLSTM recurrent model on a Gen-2 NPU. | This proves software-level recurrence, not optical state retention or conversion-free recurrent chaining. |
| Detector and CMOS path | LRZ reports photodetection, digital electrical outputs when further processing is required, on-card CMOS, continuous exchange between photonic and classical units, 16-bit conversion, and detector noise. | The current architecture may pay the exact full-conversion cost that eliminated the modeled R1 full-regeneration path. The wording does not reveal whether selected native operations can be chained before that boundary. |
| Integration and scaling | Q.ANT uses z-cut lithium niobate on insulator, low-loss waveguides, electro-optic switching, on-card lasers, and a CMOS/PCIe system. Its patent record includes mitigation of electrical stray fields across large modulator arrays. | The physical stack and correlated-error problem are credible engineering targets. A patent and product description are not measured R1 drift or crosstalk evidence. |

Q.ANT's AI accuracy, 16-bit conversion, model accuracy, and application
speedups are explicitly inadmissible as consensus-exactness evidence. Likewise,
"native nonlinear" does not mean that the optical transfer produces identical
symbols across devices, temperatures, calibrations, or zero-margin inputs.

## Native-operation audit

### Verified publicly

- direct matrix-vector access through Q.PAL in C/C++ and Python;
- a low-level system-control API and Linux driver;
- native nonlinear optical units in the Gen-2 product;
- a weighted sinusoidal optical operation described in Q.ANT's 2026 use-case
  paper;
- on-card photonics, lasers, CMOS, shared memory/I/O windows, and PCIe Gen4 x8;
- software execution of recurrent and iterative AI models.

### Not verified publicly

- the specific mathematical transfer and parameter range of the nonlinear
  element;
- whether the weighted sinusoid is exposed as a stable cosine primitive;
- native ReLU, sigmoid, softmax, threshold, sign, wrap, or programmable
  hysteresis at the physical-operation level;
- maximum matrix and vector dimensions, input alphabet, accumulator behavior,
  weight residency, or batch layout at the low-level interface;
- raw detector samples, decision margins, calibration state, or uncertainty
  flags through the public API;
- photonic-to-photonic chaining without a general ADC, digital state
  reconstruction, DAC/modulator drive, or host-visible round trip;
- per-channel detector, conversion, decision, correction, and re-entry energy;
- symbolic error probability or worst-case behavior near a quantization
  boundary.

The claimed cosine operation must therefore be treated as **unconfirmed API
detail** until Q.ANT supplies documentation or an experiment. The public record
supports a weighted sinusoidal transfer, which is enough to justify the
investigation but not enough to model an exact boundary.

## R1 operation mapping

The representative R1 transition is:

~~~text
y[t]   = M * s[t]
s[t+1] = low_bits((y[t] + offset) >> shift)
~~~

| R1 operation | Existing-NPU status |
|---|---|
| Encode exact signed low-bit state | Plausible; supported numeric range and encoding must be confirmed. |
| Resident matrix-vector operation | Publicly supported in principle; R1 dimensions and persistent-weight behavior are unknown. |
| Read accumulator or detector margin | Unknown; raw or sufficiently calibrated output access is not public. |
| Exact low-bit wrap | Not demonstrated. A smooth sinusoid is neither an exact quantizer nor a deterministic tie rule. |
| Guard-band decision and selective digital fallback | Architecturally plausible because CMOS is present, but no suitable low-level path or cost is published. |
| Feed exact state into the next optical pass | Unknown. The recurrent AI demonstration does not disclose where state resides between steps. |
| Two linked R1 rounds without host/PCIe materialization | Unknown and decisive. |

Therefore, representative R1 work is **partly executable on existing hardware**:
the matrix pass and a nonlinear-surrogate experiment are supported by public
evidence. A byte-exact two-round R1 experiment is conditional on low-level
detector access, exact assistance, and a documented re-entry path. This is a
vendor-capability question, not grounds for a custom build yet.

The public 8 GOPS figure does not establish that a full 8192-by-8192 R1 attempt
fits on the current NPU or is economically competitive. The first experiment is
a supported-size physical projection of the same residue, margin, and chaining
problem, not a production-scale miner benchmark.

## Existing-NPU experiment

### Stage 0: capability confirmation

Ask Q.ANT to identify, at the physical and API levels:

1. the transfer function and controls of every native nonlinear element;
2. whether weighted sinusoidal or cosine output can feed another optical
   operation without host memory or a general-purpose conversion cycle;
3. the conversion boundary for matrix output, nonlinear output, and recurrent
   state;
4. access to raw detector values, margins, calibration data, and per-channel
   status;
5. supported dimensions, signed ranges, weight persistence, batching, and
   deterministic execution controls;
6. availability of a one-bit or low-bit comparator, hysteresis, programmable
   guard band, or on-card selective-correction hook; and
7. card- and server-level power telemetry synchronized with kernel execution.

The key deliverable is a block diagram marking every detector, TIA, sample or
hold, ADC, CMOS operation, memory crossing, DAC/driver, modulator, and optical
re-entry between two native operations.

### Stage 1: single-pass characterization

Run a supported-size projection of the frozen R1 matrix/vector distribution.
For each exact digital input:

- retain the CPU integer result as the authority;
- collect raw or highest-resolution NPU output over repeated trials;
- sweep all represented bucket residues, especially exact and near ties;
- measure independent error, channel correlation, common-mode drift,
  temperature sensitivity over the declared 15--35 C range, calibration age,
  and run-to-run repeatability; and
- record card energy, server energy, latency, and throughput separately.

AI task accuracy is not recorded as an exactness result.

### Stage 2: native nonlinearity characterization

Exercise the weighted sinusoidal or other lowest-level nonlinear primitive
directly. Fit its physical transfer only to describe the device, not to infer
consensus behavior. Measure noise and drift versus distance from each proposed
decision boundary and determine whether a stable guard band can be defined.

If the native operation cannot expose its transfer or intermediate output, a
Q.ANT-run measurement with raw results is required before proceeding.

### Stage 3: two-round path comparison

Measure three paths over the same supported-size R1 projection:

1. **Full conversion control:** optical MVM, general conversion, exact digital
   wrap, full re-encoding, optical MVM.
2. **Selective assistance:** optical MVM, low-bit guard decision, exact digital
   recomputation only inside the guard band, re-entry, optical MVM.
3. **Native chained surrogate:** optical MVM, native sinusoidal nonlinearity,
   next optical operation without an exposed digital state, if supported.

Only paths 1 and 2 can produce an R1 exactness result. Path 3 measures whether
Q.ANT can avoid a conversion boundary and whether a future construction family
might use the physical transfer; it cannot validate R1 by approximation.

### Stage 4: valid-attempt accounting

For every path report:

~~~text
J_valid = (J_matrix + J_detection + J_conversion + J_boundary
         + J_control + J_assist + J_drive + J_remodulation
         + J_hashing + J_recheck) / P_exact
~~~

Measure idle-subtracted and total card energy, total server energy, exact-output
yield, guard-band hit rate, assistance success and energy, calibration
amortization, and valid throughput at equal board power. Q.ANT's 8 GOPS and
150 W product specifications must not be converted into R1 economics without a
matched operation definition and measured utilization.

## Decision rules

- If every recurrent step requires general 16-bit conversion, complete digital
  state reconstruction, and full optical re-encoding, classify Q.ANT as a
  measured full-regeneration path and evaluate it against the existing 3x and
  5x gates. Do not keep the physical-boundary question open on architectural
  wording alone.
- If the NPU supports on-card chaining but only through a smooth analog
  nonlinearity, retain it as a future-construction probe; do not count it as
  exact R1 regeneration.
- If raw detector access or an exact assistance hook is unavailable, request a
  vendor-run experiment before designing custom hardware.
- If a guard-banded path is exact and avoids full conversion for unambiguous
  lanes, insert its measured energy, latency, error correlation, and assistance
  rate into the frozen simulator. R1 reopens only if the conservative result
  reaches 3x, with a credible path to 5x.
- A custom laboratory build is justified only after the existing NPU is shown
  to lack a required interface while its measured internal path demonstrates
  that a purpose-built low-bit boundary could plausibly fit the charter budget.
